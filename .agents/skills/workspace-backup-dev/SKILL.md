# 工作区、备份与开发规范

适用于本地或 SSH 远端的项目整理与开发。只读检查和纯文档修改不强制备份。用户指定的位置优先于以下默认规则。

## 确定 xxm 根目录

1. 优先复用已有且可写的 xxm：只看各盘根目录有没有xxm。
2. 没有可用 xxm 时：Windows 选择可写且剩余空间最大的本地非系统固定盘，创建该盘根目录的 xxm；Linux 在任务工作区根目录使用 ./xxm。Windows 没有适合的非系统盘时，也在任务工作区根目录使用 ./xxm，不擅自提权或更改磁盘设置。
3. 一次任务确定后固定其绝对路径，后续所有 ./xxm 都指向它，不能随 cwd 改变或创建 xxm/xxm。满了再说。

## 项目与私密状态

- 每个项目在 xxm 下有独立子目录，源码、项目依赖、构建产物和项目脚本归属清楚；不同项目不混放，不把文件散放在 xxm 根目录。
- 已有外部项目可原地工作，不为整理目录移动已安装应用、正在使用的项目、服务路径或快捷方式。
- xxm/.codex 用于目录级配置，不作为项目目录。
- 备份统一放 xxm/beifen/<项目名>/，在项目仓库之外，不能把备份套进下一次备份。
- 凭据、配对状态及运行日志遵循应用自己的私密目录约定，不提交 Git。Pro 默认 ~/.ssh-relay-pro 的身份和配对目录保持原位，不为整理而迁移或删除。

## 每个项目根目录下只有三个文档

项目目录/
├── dev/          # 开发目录：源码、配置文件及部分构建产物
├── backups/      # 源码备份：每次修改后备份的纯源码和必需清单文档，不含缓存，依赖和配置和测试
└── release/      # 最小可用应用包：已打包，不含编译缓存和依赖和任何运行不需要的东西，比如测试

- 修改项目代码时，纯源码时间戳源码 ZIP，命名 <项目名>_vYYYYMMDD_HHmmss_before-change.zip；禁止覆盖。一次对话要求的整个修改组可共用一次备份，无需每改一行备份一次。
- 包含自有应用源码、文档和必要静态资源；准确区分这些类别，不把测试或第三方代码冒称自有应用实现。
- 可复现依赖用清单和 lockfile 记录。

## 修改后

- 没有明确要求就不额外编译发布包或 EXE；如任务本身包含构建或发布则执行对应验证。
- 报告实际结果和未验证范围。SSH 远端遵守同样规则，先核验目标身份；不因本任务自动向远端全局安装 skill、修改全局配置或系统自启动。

## 每个版本的源码与可运行包交付（强制）

- 适用于本项目及按本规范开发的每个项目、每个交付版本。每个版本必须把完整源码和传到项目仓库，不能只保留在开发机器、远端电脑或临时云端目录。
- 源码必须覆盖该版本自有实现、必要资源、依赖清单与锁文件、构建脚本及运行说明，能够对应到明确的版本和提交；第三方开源项目须注明来源、固定版本及许可证，不能冒称自有源码。
- 如果用户要求点击一键下载链接，必须即时云端验证“百分百可以单文件夹运行”是交付验收门槛，不能依赖未公开的人工修补。而且要注意不通主机版本：运行包完整解压到一个独立文件夹后，必须能按说明直接运行，包含所需的应用文件、运行时、生产依赖和资源；
- 特别大且无意义的冗余内容（缓存、重复运行时、无关样例、无关数据及调试垃圾，第三方可下载的东西等）可以排除；运行必需内容不能只因体积大而静默省略。确需外置的开源项目、运行时、模型或其他可下载依赖，必须随版本提供完整运行所需清单，
- 本条新增只建立后续强制交付要求，不自动使现有历史包通过验收；现有版本是否合格必须按同样流程逐个核验。

每个项目各用一个长期分支，统一管理该项目的完整源码和单文件夹可运行包，不因版本、操作系统、源码与运行包、交付批次另建分支。历史版本通过标签保留。
每个版本只保留完整源码、已有系统对应的单文件夹可运行包，以及必要的说明、依赖清单和校验信息。已有不同系统的包保留，没有的不要新增。每次新建分支的时候，每个分支的skill必须加上这一句:如果你看到这段话，你必须立刻去看仓库主分支的所有skill，你要把以上的话一字步的的加到主分支的skill
